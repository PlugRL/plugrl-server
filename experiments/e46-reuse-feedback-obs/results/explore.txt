Reading: WebSocketAgentServer's scheduler loops on
`await asyncio.sleep(SCHEDULER_SLEEP_INTERVAL)`, 0.1 ms since E5. On Linux,
asyncio waits in epoll_wait, whose timeout has millisecond resolution, and
Python's selectors module rounds a positive timeout up to 1 ms. An infer
queued while the scheduler's 0.1 ms timer is still pending, with no further
network event coming, is therefore picked up up to a millisecond late. How
often that happens depends on the phase between the handler and the
scheduler. v2's extra microseconds in the handler shift that phase, so v2
loses less, and the profiler hides the gap entirely. With the sleep at 0,
both kinds of client get answers in 0.9 ms, and the reuse arms no longer
differ.

So the Part B speed-up is not reuse's, and the cost belongs to every
plugrl-server run on one machine: about 1.3 ms of a 2.2 ms round trip here.
A sleep of 0 busy-polls a core and is not the fix. The scheduler should
wake when there is work. That is a separate change, measured separately.
